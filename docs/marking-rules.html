A rule is a pure function of one context

Every rule has the same shape: it receives a Ctx built once per dataset and returns an array of marks. It reads nothing else, keeps no state, and cannot see the reader’s settings. 

interface Rule {
  id, group, label, blurb, phrase?
  defaultOn: boolean        // density: does it paint the chart out of the box
  tier?: 'extra'            // usage: does the rules card fold it away
  detect(ctx: Ctx): Mark[]
}

interface Ctx {
  data    // the Dataset: d[], o[], h[], l[], c[], v[], rolls[]
  m       // Metrics  — one pass of per-bar columns
  s       // Structure — pivots, legs, trend, pullback
  tick    // minimum price increment, from instrument.ts (0.25 for ES)
  tol     // multiplier on every ATR tolerance; 1 by default
}

buildCtx(data, opts) = {
  m = metrics(data)
  s = structure(m, { strength, minSwingAtr })
}

detect() runs the enabled rules in registry order, concatenates their output, drops any mark whose id has already been seen, and sorts the result by at then by rule id. The sort belongs to detection rather than to whoever consumed it: the chart wants markers in time order, the tape reads top-down, and the CLI report is a table.

The dedupe is a backstop, not the mechanism. Rules are expected to produce distinct ids and each is fixed when it does not — --check asserts uniqueness per rule, because checking detect()’s output would only prove the backstop works.

tol scales ATR tolerances and nothing else

Above 1 it loosens every rule at once. Look down the scaled by tol column below and the pattern is exact: every threshold denominated in ATRs takes it, and every ratio, count and bar-window does not. The one deliberate exception is DEFAULT_MIN_SWING_ATR, which is a structure option rather than a rule threshold and is applied without it.

The columns every rule is written in

metrics() makes one pass over the dataset and produces the per-bar quantities that "trend bar", "doji", "shaved", "big" and "gap" are definitions over. Typed arrays, computed exactly once — thirty-one rules each rebuilding this over 6,550 bars would be thirty-one times the work for identical numbers.

Three things here are not arithmetic

  • Contract-aware true range, on the right bar. The gap across a contract change is carry. Dataset.rolls holds the expiry sessions; the discontinuity is the session after, where the new front month opens. So tr and gap are suppressed at contractStarts(), one bar later. The chart marks 2024-12-20 and the +2.77% of carry lands on 2024-12-23 — getting this off by one leaves the carry in ATR while suppressing a real move next to it.
  • Self-consistent extremes. On ten of the 6,550 sessions the feed prints a close outside its own high/low — eight are quarterly expiries carrying the settlement price, and two are plain dirt. Left alone they push closePos past 1 and would fire shaved and reversal-bar on a bad print. So m.high and m.low are the printed extremes widened to enclose open and close, every ratio is computed against those, and suspect marks where the widening was needed. Rules read m.high / m.low, never data.h / data.l, so the correction cannot be bypassed by accident.
  • Nothing is skipped here. isRoll and suspect are reported, not acted on. A bar rule wants to decline those sessions; a line rule legitimately spans them.

The two guards

Which of the two a rule uses is the single most consequential line in it, and the reason there are two is that a session can be unusable for two unrelated reasons. 

usable(m, i)      =  m.suspect[i] === 0

comparable(m, i)  =  i > 0
                  && m.suspect[i] === 0
                  && m.suspect[i - 1] === 0
                  && m.isContractStart[i] === 0
  • usable — the bar’s own geometry can be trusted. Enough for any rule reading one bar: trend-bar, big-bar, doji, shaved, pin-bar, climax, gap-bar.
  • comparable — and so can its comparison against the session before it. Required by everything that reads i − 1: inside, outside, ii, ioi, reversal-bar, breakout, follow-through, two-bar-reversal, and every entry rule’s scan.

Structure: pivots, always-in, and the pullback count

Everything in the lines and entries groups is written against this rather than against raw bars. Brooks reads swings by eye; the eye is not available here, so a strength-N fractal stands in. 

fractals(m, strength):
  for i in [strength, n - strength):
    isHigh = for all k in 1..strength:  high[i] >  high[i-k]   // STRICT left
                                    and high[i] >= high[i+k]   // inclusive right
    isLow  = the mirror

    // An outside bar can satisfy both. It is one bar and cannot be two
    // pivots, so the LARGER TAIL decides which extreme was rejected.
    if isHigh and isLow:
      upperTail[i] >= lowerTail[i] ? isLow = false : isHigh = false

    emit { i, kind, price, confirmedAt: i + strength }

The left/right asymmetry is what resolves a plateau: where two adjacent bars share a high, the earlier one is the pivot and the later one fails its own left test. Without it a flat top emits a pivot per bar.

The reduction is streaming, not global

Raw fractals do not alternate — runs of two or three highs with no low between them are ordinary. They are folded into an alternating sequence in confirmation order, and trend, pullback and lastPivot are written from the reduction’s state at each bar. Nothing later than bar i can reach back and change what bar i knew. 

admit(kept, p):
  last = kept.last
  if none:              kept.push(p)
  else if same kind:    if p is the further extreme, REPLACE last
  else:                 floor = isFinite(atr[p.i]) ? atr[p.i] * minSwingAtr : 0
                        if |p.price - last.price| >= floor:  kept.push(p)

readTrend(kept):                             // the last FOUR pivots
  fewer than 4                         -> 0
  not exactly 2 highs and 2 lows       -> 0
  higher high AND higher low           -> +1   always-in long
  lower  high AND lower  low           -> -1   always-in short
  otherwise                            ->  0   trading range

Doing that reduction as a global fixed point instead would let a swing in 2012 delete a pivot from 2011, and every trend value before it would silently become a fact from the future. --check proves the absence of lookahead rather than asserting it: it rebuilds the whole structure from the series with its last 500 sessions removed and requires every earlier trend and pullback value to be identical. 0 of 6,050 drift, against 3,981 non-zero values compared.

One consequence is worth holding on to: pivots and legs are the reading as of the last bar, while trend, pullback and lastPivot are the causal per-bar record. They can disagree about the recent past, and that disagreement is correct.

The pullback counter

per bar, once the trend state is known and unchanged:

  bull (trend === +1):
    pulling AND high[i] > high[i-1]  ->  count = min(count + 1, 4)
                                         pullback[i] = +count      // H1..H4
                                         pulling = false
    high[i] < high[i-1]              ->  pulling = true
    high[i] > legExtreme             ->  legExtreme = high[i]
                                         count = 0                 // RESET

  bear: the mirror, writing -count   // L1..L4

  a change of trend state resets count, pulling and legExtreme,
  and nothing is counted on the bar the state flipped

The reset at a new swing extreme, rather than only on an attempt bar, is what keeps the distribution honest: the leg resumed, so whatever comes next is a fresh pullback starting at H1. Without it the count runs away through a grinding trend and everything piles into the H4 bucket. The healthy shape is a geometric decay — currently 529 / 167 / 70 / 66.

Fitting a line, and asking something of it

Channel, wedge, triangle and spike-and-channel are the same two moves — fit a line through some pivots, then ask something about the result — and differ only in which pivots go in and what is demanded of the slopes. Keeping the fitting in one file means the tolerance, the touch test and the break test have one definition each. 

fitLine(points)          // ordinary least squares over (bar index, price)
                        // null for fewer than 2 points, or zero variance in i
lineThrough(a, b)       // the exact line through two points
priceOn(line, i)        // intercept + slope * i

measure(line, m, from, to, side, tol, close):
  side = +1  the line is a FLOOR tested by lows
  side = -1  the line is a CEILING tested by highs

  for i in [from, to]:
    at      = priceOn(line, i)
    extreme = side === 1 ? low[i] : high[i]
    gap     = side === 1 ? extreme - at : at - extreme    // negative = past it

    |gap| <= tol                    ->  touches++
    gap < -excursion                ->  excursion = -gap
    side === 1 ? close[i] < at - tol
               : close[i] > at + tol ->  breaks++         // on the CLOSE

envelopeOffset(line, m, from, to, side)
  // the parallel offset that encloses every bar on the other side
  • Everything works in (bar index, price). Not dates, because a line has to be evaluated between and beyond its anchors; not pixels, because a rule must give the same answer at every zoom.
  • A break is measured on the close, not the extreme. A wick through a trendline is what trendlines are for; counting those as breaks rejects every real channel on the chart.
  • excursion is computed and returned but no rule currently reads it. It is the furthest any bar reached past the line, kept for a quality test that has not been written.

From signal bar to trade

Brooks defines the entry mechanically — a stop order one tick beyond the signal bar, the protective stop one tick beyond its other end — so the prices are not a judgement call. The entry rules do no arithmetic of their own, which is why "where is the stop" has one answer across all eight of them. 

planFor(ctx, signal, dir, target?):
  entry  = long ? high[signal] + tick : low[signal]  - tick
  stop   = long ? low[signal]  - tick : high[signal] + tick
  risk   = |entry - stop|                      // must be > 0
  target = target ?? entry ± DEFAULT_TARGET_R * risk        // 2R

walkForward(ctx, plan, orderAt):
  // 1. THE ORDER IS LIVE FOR EXACTLY ONE BAR
  for i in (orderAt, orderAt + FILL_WINDOW]:
    touched = long ? high[i] >= entry : low[i] <= entry
    if touched:
      fill  = long ? max(open[i], entry) : min(open[i], entry)   // GAPS TAKE THE OPEN
      start = i
  no fill  ->  { outcome: 'no fill', r: 0 }

  // 2. R is measured from what was actually PAID
  risk = |fill - stop|

  // 3. resolve, in this order, from the fill bar onward
  for i from start:
    i > start && isContractStart[i]  ->  'open', scored at close[i-1]
    hitStop                          ->  'stop',   ambiguous = hitTarget
    hitTarget                        ->  'target'
  never resolved                     ->  'open', scored at the last close
  • A bar containing both stop and target is a loss. Daily OHLC cannot say which came first, and assuming the good one is how a backtest talks itself into an edge. ambiguous counts them so the number stays auditable rather than buried.
  • A bar that gapped through the entry fills at the open, not the order price — and R is measured from the fill, so a bad fill costs the trade rather than being rounded away.
  • The order is live for exactly one bar. A buy stop above yesterday’s high is an order for today; leaving it working for a week turns every failed setup into a different, later trade nobody took.
  • The walk is lookahead by construction. Nothing that decides whether a mark exists may read it — it is confined to the mark’s note and its through date.
  • orderAt is not always the signal bar. Five rules sign at their signal bar’s close; the three anchored on a swing pivot — dt-short, db-long, wedge-reversal — pass the confirmation bar, three sessions later.

Reversal bar

reversal-bar on by default

Takes out the previous extreme, then closes back through it in the far third of its own range — and does so at a genuine extreme.

340marks
5.2%of sessions
13a year
comparableguard
atknownAt
bar · R▲ R▼emits

Predicate

comparable(i) && range[i] !== 0
bodyPct[i] > DOJI_BODY                     // a doji that dipped is not a reversal

bull =  low[i] < low[i-1]
     && dir[i] > 0
     && closePos[i] >= REVERSAL_CLOSE      // 2/3
     && close[i] > close[i-1]
     && isExtreme(i, 'low')

bear =  high[i] > high[i-1]
     && dir[i] < 0
     && closePos[i] <= 1 - REVERSAL_CLOSE  // 1/3
     && close[i] < close[i-1]
     && isExtreme(i, 'high')

isExtreme(i, 'low')  =  no k in [i-10, i-1] with low[k]  <= low[i]
isExtreme(i, 'high') =  no k in [i-10, i-1] with high[k] >= high[i]

Notes

  • The context test is what makes the rule mean "a turn". Without it the pattern fires on any strong close that dipped first — one session in six, 22% of the series. With it, 5.2%.
  • REVERSAL_LOOKBACK is a plain 10-bar window and deliberately not a swing pivot: a pivot is not confirmable for another three bars, and this rule promises to be readable at the close.
  • The comparisons in isExtreme are non-strict (<=, >=), so a tie with any bar in the window disqualifies it.
  • The close-against-close test is separate from closePos: the bar must both finish in the far third of its own range and beyond the previous close.

Lines — the shapes those bars build

Eight rules over ctx.s.pivots rather than raw bars — with one exception, micro-channel, which reads bars directly and is therefore the only shape here readable on the day it completes. For the other seven, knownAt is the confirmation date of the last pivot the pattern depends on, never the date of its own last point.

Bull channel

A least-squares trendline through a run of rising swing lows, with the parallel that encloses the highs.

Predicate

// runs(pivots, 'low', +1): consecutive LOW pivots each strictly higher
// than the last. A run ends where one is not; runs of >= 2 are kept and
// sorted LONGEST FIRST.

  skip if [run.first.i, run.last.i] overlaps an already-claimed range

  • knownAt is the largest confirmedAt in the run — the channel is not readable until its last pivot confirms, three sessions after it printed.
  • A touch is within 0.4 × ATR either side. A break is a close beyond the line by more than that tolerance — a wick through a trendline is what trendlines are for.

Wedge

wedge on by default

Predicate

// findWedges(ctx) — shared with wedge-reversal
for each sliding window of FIVE alternating pivots:
  skip if the window overlaps an already-claimed range

  pushes = the 3 pivots of the window's FIRST kind
  pulls  = the 2 of the other kind

  • A sliding window means a genuinely coiling stretch satisfies the predicate at four consecutive positions; the claimed-range list keeps the earliest complete reading — the one a trader would have drawn first.
  • The two segments share an id stem and differ by a push / pull suffix.

  • The breakout must be the immediately following bar. The outer loop is written with a FLAG_FAIL_WINDOW bound but always terminates on its first iteration, so that bound never takes effect; the flag’s breakout is exactly end + 1.
  • The flag is grown greedily and stops at the first bar that would widen it past 2 × ATR, so overlapping start positions produce flags of different lengths and the claimed set keeps one mark per failure bar.
  • The best average in the set at +0.462R, and the only rule here whose target is a plain 2R and still comes out clearly positive.
